01

The patterns

Five findings that hold across all 100. Every number here is a count over data/findings.json and recomputable from the repo.

{{AUTH_KEY}}/{{AUTH_OAUTH}}

API keys beat OAuth2, and that is the easy half

{{AUTH_KEY}} apps lead with a static key or token, {{AUTH_OAUTH}} with OAuth2. A key is a one-line integration; OAuth2 is a redirect, a token store and a refresh loop. Composio's managed auth erases exactly that difference, so the auth split predicts build cost, not feasibility.

50%

Marketing & Ads is the gated category

Only half of the ad platforms are open. Google Ads, Meta Ads, LinkedIn Ads, Pinterest and Threads each put a human review between you and a production token. No other category comes close — Developer Infra and Productivity are 100% open.

{{SALES}}

The real blocker is a sales call, not a spec

{{SALES}} apps require a partnership, enterprise contract or booked call before any credential exists. Every one of them has perfectly good public documentation. The blocker is commercial, which means it is solved by outreach, not engineering.

{{CX_OPEN}}/{{CX_GATED}}

Coverage already tracks openness

Composio ships toolkits for {{CX_OPEN}}% of the self-serve apps but {{CX_GATED}}% of the gated ones. The catalog has naturally grown along the path of least resistance — which is where the remaining {{OUTREACH_N}}-app outreach list comes from.

{{NONEAPI}}

Two apps are not apps

Sherlock and Mermaid CLI are open-source command-line tools with no hosted service and nothing to authenticate against. Listing them as "blocked" would be wrong: they need a sandboxed exec wrapper, which is a different product decision entirely.

03

What to do about it

The map only matters if it changes a queue. It splits the 100 into three piles with different owners.

{{EASY_N}} Easy wins — ship, don't ask

Self-serve credentials, buildable today, no Composio toolkit yet. An engineer can start any of these this afternoon without talking to the vendor.

{{EASY_CHIPS}}

{{OUTREACH_N}} Needs outreach, not engineering

Sales or partnership gated. The work here is a conversation and a contract. Shipping order should follow who answers the email, not who has the nicer API.

{{OUTREACH_CHIPS}}

{{REV}} Review gates — budget the wait

Self-registration works, but production access needs an approval that takes days to weeks: Amazon SP-API quotes 1–2 weeks, Pinterest wants a demo video, Meta needs 500 API calls in 15 days before you can even apply.

Where a human was needed

Slug resolution. Composio's slugs are not derivable from app names — Zoho CRM → zoho, Otter AI → otter_ai_mcp. 41 of 100 needed a hand-written alias. They live in one audited dict in agent/composio_catalog.py.

Judging "gated". No page says "we are partner-gated". You infer it from a Request access button, a missing price, or a help article that contradicts another one. Ahrefs publishes two articles that disagree about whether its API needs Enterprise. A classifier picks one; a human records the conflict.

Knowing when to stop. For iPayX, the correct output is "not found". Every search returned a different company called iPay. The valuable behaviour was refusing to fill the cell.

Design decisions worth defending

No LLM in the scoring path. Every number on this page is a count, not a model output. The model's job was reading documentation; arithmetic is Python's. That is why the patterns are reproducible.

Provenance per row, not per dataset. Each row carries the tier of evidence behind it. Averaging a confident row with a guess hides exactly the thing a reviewer needs to see — and the audit showed the tiers really do predict accuracy.

Composio's catalog as a second opinion. Using it as an independent source made the cross-source loop possible and caught two bugs in my own normaliser.

07

What this does not prove

The brief asked for honesty about what defeated the agent. These are the limits a reviewer should push on.

One host was reachable, not one hundred

The sandbox this ran in allowed egress to composio.dev and github.com only. Composio's catalog was fetched and parsed for real; vendor documentation was reached through a search tool that returns primary URLs and quoted passages rather than by loading each page. So evidence links are real and were returned by the research pass, but most were not re-opened byte-for-byte at render time.

{{V_PRIOR}} rows rest on model prior

They are labelled prior in the table and are the first rows to re-check. The audit found both of its misses in exactly this tier, so the label is doing real work rather than hedging.

"Official MCP" is under-counted

{{MCP}} apps are marked as having an official MCP server, established from evidence encountered during research. There was no way to probe every vendor's /.well-known from this sandbox, so the true number is probably higher. Absence here means "not found", never "does not exist".

Gating changes faster than docs

Google sunset Google Ads developer tokens on 2026-09-09 and moved access levels onto Cloud projects. That post-dates the model's training data and was caught only because the research pass ran. Anything in this table is a snapshot, and the ad platforms move the most.

Two vendors defeated the research

iPayX — no documentation found at all; every result was a different company. Paygent Connect — identifiable only as an NMI-powered gateway, with no Paygent developer portal. Both are recorded as low confidence rather than filled with a plausible guess.

One category boundary is arguable

Plaid moved from self-serve to review-gated during the audit because sandbox keys are instant but production access is a separate reviewed request. Several rows sit near that line; the taxonomy, not the data, is what makes them debatable.
